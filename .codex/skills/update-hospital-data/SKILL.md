# 更新醫院資料

事實異動須有當次取得、能追溯且適用於目標院所的證據。以欄位為單位完成可確認的更新，保留未解項目。

預設執行基準為 **GPT-6 Luna／max**（`gpt-6-luna`、`reasoning_effort: "max"`）；這是使用建議，不會切換已啟動的主 agent。使用者指定優先，多院 worker 設定見下方參考文件。

每院依序完成：**定範圍 → 查來源 → 列異動 → 潤飾文字 → 改檔 → 驗證**。工作筆記只保留目標、證據、待改值與未解欄位；證據足夠就前進，不反覆重查已裁決項目。

## 入口與閱讀範圍

| 使用者任務 | 執行範圍 |
| --- | --- |
| 指定電話、時間等欄位 | 只查該欄位及相依欄位 |
| 只潤飾既有文字 | 只處理指定文字與必要的修改日期；不算重新查核 |
| 查核／更新一間醫院 | 完整條目，含公告、特別門診及 Google 資訊 |
| 新增、改名、搬遷 | 完整條目與同院辨識，先排除重複 |
| 多院或縣市查核、更新、實測 | 先列目標清單；指定縣市而未指定抽樣時，涵蓋該縣市既有有效條目，並搜尋尚未收錄的特寵院所；查核、去重後逐批更新或新增，不宣稱已找齊全市院所 |
| 以既有更新資料撰寫 Threads 貼文 | 使用當次已確認資料，依當月適用期間整理與潤飾；只補影響文章正確性的缺項 |
| 修改本 skill | 只維護 skill 與相關參考檔，不啟動醫院查核或多院委派 |

依本輪工作讀取，不預先載入所有參考檔：

- 查核或更改事實：讀 [欄位判定](references/field-rules.md) 的相關章節。
- 新增、修改醫院資訊文字：必讀 [文字潤飾](references/writing.md) 及其中指定的 `humanizer-zh-tw`。同一上下文已讀過可沿用。
- 資料更新收尾或使用既有更新撰文：讀 [本月 Threads 文案](references/threads-post.md)，選出影響就診的重點並用 humanizer-zh-tw 潤飾。
- 處理日期、公告或更新動態：讀 [日期與更新紀錄](references/update-records.md)。
- 縣市名單更新或明確要求補漏：必讀 [查找清單外院所](references/discovery.md)，搜尋未收錄院所；明確限定既有條目、抽樣或單欄位時遵守限定。
- 實際查核兩間以上：另讀 [多院委派](references/multi-hospital.md)，預設每批最多 2 間；使用者指定本次數量時依其上限，主 agent 統一改檔。維護 skill 或只潤飾文字不啟動查核委派。

## 不可破壞的資料原則

- 「沒找到」不等於「已取消」。證據不足或衝突未解時保留原值；缺少的選填欄位維持未填。未知不補成 `false`、`[]`、零或空字串。
- 物種、服務、專長、特寵急診與門診限制須由院方明確支持；不從動物照片、評論、個案或醫師經歷推定現行受理範圍。
- 每項事實的新增、覆蓋或刪除都要有依據。既有 `id` 與 `createdAt` 保持穩定，例外依欄位判定處理。
- 修改限目標醫院與必要更新紀錄；保留既有使用者修改、註解、排序與格式。跨院時間窗清理僅依日期與更新紀錄的流程執行。
- 中文檔案以 UTF-8 讀寫；PowerShell 明確使用 `Get-Content -Encoding utf8`。疑似亂碼先重讀。
- 工具故障、未解衝突及查核過程寫在回報，不寫進使用者會看到的醫院資料。

## 1. 建立本輪基準

1. 查看 `git status --short`、目標檔案的 staged／unstaged diff，記錄既有修改；後續以本輪開始時的內容比對，不能把整份 diff 都算成本輪成果。
2. 讀 `src/types/hospital.ts`，以 `rg` 定位並完整讀取目標物件、相關更新紀錄。縣市補漏、新增或跨縣市搬遷另查 `src/lib/getHospitals.ts` 的實際匯入清單；`src/utils/hospitals.ts` 不是目前彙整入口。註解中的物件是歷史線索，不能當成已收錄的有效條目。
3. 欄位契約以當前型別與使用端為準。`docs/hospital-field-reference.md` 與 `scripts/normalizeExoticHospitalData.cjs` 含舊欄位、固定日期及未知值預設，不當作現行規則，不執行全站正規化。
4. 記錄 `id / name / address / 檔案 / 查核範圍`，以官方入口、地址、電話等交叉確認分院。無法辨識的院所暫停寫入，其他院所繼續。
5. 取得 `Asia/Taipei` 當次日期作為 `CHECK_DATE`，不可抄舊資料日期：
   `node -e "console.log(new Intl.DateTimeFormat('en-CA',{timeZone:'Asia/Taipei'}).format(new Date()))"`

縣市名單更新依 [查找清單外院所](references/discovery.md) 建立全站收錄索引、搜尋並去重候選，再把符合範圍的候選排入查核批次；不能只查既有清單就收尾。

完整查核逐組記錄完成度：身分位置、聯絡預約、固定時間與急診、物種服務分類、特別門診、公告、Google／社群、後設日期。不能只因開過網站就稱全院已確認。只潤飾文字時，定位目標並記錄基準後跳至步驟 4，以既有文字為原稿，不提升原資料的可信度。

## 2. 取得並裁決來源

來源優先序：院方官網／正式公告／預約系統 → 官方社群 → Google Maps 商家頁 → 政府或可信公開資料 → 第三方線索。這是查找順序；判定仍須核對分院、適用範圍與生效日。

- 從現有 URL 找官方入口，再以院名與縣市／地址核對歸屬。搜尋摘要只用來定位，必須讀原文；圖卡須實際看圖。
- 公告與更新動態另依 [公告來源連結](references/field-rules.md#公告來源連結) 選取事件原文；查找順位不等於儲存網址順位，不能因先讀到官網班表就省略原文連結檢查。
- 同為官方資料，採直接對應該分院、較具體且已生效的內容。新的正式異動公告可取代未同步的官網頁尾；較新行銷文不能推翻具體就診限制。
- 先分辨是否在說同一件事：醫療時間與百貨時間、掛號截止與收診、醫師專長與分院門診、檢體送驗與現場診療都可能不同，不能混成衝突。
- 能依來源歸屬、時效與範圍裁決，就採用並簡述理由；只有仍無法裁決的欄位列為衝突。不因 Google 與院方不同就一律保留過時值。
- 無刊登日期的固定頁面記「未標示」。月份、相對日期、置頂順序或 URL 數字不能單獨證明年份或是最新貼文。
- 未來才生效的搬遷、時間或服務異動先記公告，不提前取代現行欄位。日期到達時仍須重查是否如期實施。

### 工具與停止條件

使用當前可用的搜尋、網頁讀取及瀏覽器工具，依其文件操作，不假設 plugin 已安裝。Facebook、Instagram、Google Maps 優先使用可用的 Chrome 與既有登入狀態；使用者指定工具時遵守指定。

只讀公開院所資訊；查核不包含傳訊、致電、送出預約或取得私人帳號資料。同一路徑失敗後做一次有目的的重試／診斷，仍失敗就換官方替代入口。沒有替代證據時標記受影響欄位「受阻」，繼續其他欄位。若使用者要求必須用 Chrome 而工具不可用，依賴該要求的查核保持受阻，不以其他工具冒充完成。

直接證據已足夠、適用的公告來源連結檢查已完成，且沒有待解衝突，就停止該欄位搜尋。補查只追具體缺項；改名、搬遷或服務轉移可回溯相關公告，不重做已裁決的全部查核。

## 3. 整理異動與未解欄位

在工作筆記維護下表；無須額外建立報告檔，除非使用者要求。

| 欄位／欄位組 | 目前值 → 建議值 | 判定 | 來源 URL／原文重點 | 發布日／生效期間／查核日 |
| --- | --- | --- | --- | --- |
| 實際欄位路徑 | 精確值；無異動寫保留 | 擬修改／已確認不變／證據不足／受阻 | 直接支持該值與範圍的內容 | 無法確認的日期明說 |

列出所有擬改欄位與未解項目；已確認不變的欄位可按組彙整。貼文文字、圖卡及日期須屬同一來源，不能拼接不同貼文作證。

能取得來源卻不足以支持判定，記「證據不足」；因工具或存取限制讀不到必要來源，記「受阻」。兩者都保留原值，其他獨立欄位繼續。

套用前確認：同院、仍有效、直接支持新值、相依欄位一致。位置連動 `address / city / district / lat / lng`；時間連動 `hours / business_hours`；急診連動旗標、說明與 legacy `emergency`；物種分類與預約層級依欄位判定核對。任一組未通過就保留整組，繼續其他獨立欄位。

新增院所缺少可靠的必要欄位時只回報候選與缺項，不寫入半成品。

## 4. 用 humanizer-zh-tw 潤飾文字

依 [文字潤飾](references/writing.md) 執行：**從證據整理文字草稿 → 套用 humanizer → 對照草稿核對語意 → 放回原欄位**。只潤飾任務則以既有文字作為草稿。

所有本輪新增或修改的醫院顯示文字都須經過此步驟；自然清楚的原句可以保留。查核筆記與回報的敘述也套用同樣原則，但來源原文摘錄保持原樣。完成標準是文字自然且事實、物種、預約條件、否定、日期與不確定性沒有改變；不是改了多少字或自評幾分。

## 5. 維護日期並套用

依 [日期與更新紀錄](references/update-records.md) 判斷 `updatedAt`、`last_checked`、各層 `verifiedAt` 與 HospitalUpdates。查核日、來源發布日與事件日期分開處理；例行查核、舊資料校正與新發生的就診異動也分開判定。

純文字潤飾只按規則維護院所的 `updatedAt`；不刷新 `last_checked`、各層 `verifiedAt`、貼文發布日或既有 HospitalUpdate 的 `updatedAt`，也不新增更新動態。

寫入前再讀目標物件；若與基準不同，先保留並整合新修改，不用舊快照覆蓋。事實異動須通過來源與相依欄位核對，純潤飾須通過原稿語意核對。以局部補丁套用，不重新序列化整份清單。

若修改 `HospitalUpdates.ts`，按參考文件先 dry-run 再做時間窗清理，保護本輪之前的使用者修改。單純維護本 skill 不執行清理。

## 6. 驗證與回報

- UTF-8 重讀本輪異動物件，對照基準檢查未波及其他院所、註解及既有使用者修改。
- 驗證新增／修改的醫院與更新 ID 在有效清單內唯一；公告 ID 在各院內唯一；`hospitalId` 對應有效院所。不要把註解內的 ID 當成有效重複。
- 核對完整七日時段、有效日期與期間順序、位置一致性、來源 URL、物種範圍及預約層級；只檢查欄位型別不能證明內容正確。
- 新增或替換公告來源時，實際開啟最終要存入的 `sourceUrl`，核對院所、事件與日期；檢查對應 `announcements`、`HospitalUpdates` 及 Threads 來源備查是否一致。只有網址可開啟不算通過；使用總頁作替代來源時須符合欄位判定的條件。
- 重讀實際寫入的文字：humanizer 潤飾後仍與證據表或純潤飾原稿一致，沒有擴大收診範圍、補出未證實提醒或混入查核過程。
- 資料編輯後執行 `npx tsc --noEmit` 與 `git diff --check`。目前清單彙整使用 `as Hospital[]`，型別檢查通過不能取代上述值與關聯檢查。失敗先辨別是否由本輪造成，不順手修無關問題。無資料編輯不必跑 TypeScript。
- 多院每批檢查 scoped diff，全部完成後統一執行型別檢查；只有新修改或待解失敗才重跑。

回報逐院說明：已改欄位、已確認不變的重點、保留／受阻欄位及原因、主要來源連結、是否新增 HospitalUpdates 及理由、驗證結果。指定欄位已完成就稱「指定欄位完成」；全院仍有缺項則稱「部分完成」，不掩蓋已確認欄位。多院按指定範圍列完成／部分／受阻／未處理數量與實際模型 fallback，僅完成全院範圍可稱「完整查核」。縣市任務另回報清單外搜尋範圍、候選判定、實際新增及待確認數，未搜尋或搜尋受阻須明說。驗證未執行或失敗須明說。

## 7. 產出當月 Threads 文案

資料更新及驗證完成後，依 [本月 Threads 文案](references/threads-post.md) 從本月已確認異動中，整理會改變就診安排的重要異動，院數依實際更新決定，不設固定上限。縣市貼文保留所有符合重點門檻的院所；篇幅較長時可接串文，不逐院補入沒有重要異動的條目。草稿須先經 humanizer-zh-tw 潤飾，再對照來源核對日期、分院與診療限制；在回報中一併交付。只維護 skill、純潤飾或使用者明確不需貼文時不啟動此步驟。
