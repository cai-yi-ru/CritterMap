# 欄位判定

每次資料更新閱讀，依任務使用相關章節。型別以當前 `src/types/hospital.ts` 為準；本文件提供判定規則，不取代型別。未被查核的欄位保持原樣。日期與更新動態見 [日期與更新紀錄](update-records.md)。

## 同院辨識、新增與搬遷

- 新增前搜尋院名、舊名、分院、分科、院中院及既有地址。新 `id` 依清單慣例使用穩定 kebab-case，檢查跨縣市清單沒有重複。
- 同院判定交叉比對官方公告、地址、電話、Google Place ID、網站、社群與營業主體。電話或地址相同可作線索，不能單憑一項推定合併。
- 區分全院搬遷、同院改名與部門獨立設院。部門另設新院不直接改寫原院身分；依官方證據建立新院並同步原院服務範圍與導引。醫師轉任或兼診不代表原院停止該物種門診。
- 正式改名需要官方依據；標點、全半形、括號或 Google 商家名稱格式差異不等於品牌更名。改名保留原 `id` 與 `createdAt`，同步檢查品牌、聯絡與預約入口。
- 搬遷已生效才同步替換地址與座標；座標未確認時保留整組位置欄位，先用有來源的公告說明。跨縣市須檢查資料匯出入口及是否需移至新縣市清單，不能複製成兩筆。
- 除非使用者明確要求或原 `id` 已嚴重誤導，不更換既有 `id`；確需更換時查找並同步所有引用，不能只改醫院物件。

## 聯絡、位置與 Google

| 欄位 | 寫入規則 |
| --- | --- |
| phone、address | 採同分院、已生效的院方資料；和 Google 的差異可裁決就說明採用理由。郵遞區號、台／臺或門牌寫法差異不等於搬遷 |
| city、district、lat、lng | 與地址一起核對；用商家標記或精確地址可靠座標，不用地圖視窗中心、搜尋中心或城市中心 |
| website、socialMedia | 對應院所的官方入口，社群放對應平台欄位 |
| appointmentLink | 可直接掛號、預約、聯絡排診或預約諮詢的官方入口；首頁或一般粉專不等於預約入口 |
| reservationRequired | 根層級描述全院：強制預約才為 true，明確可現場掛號才為 false；「建議／優先預約」本身不足以判定任一值。只限特寵或指定門診用 specialClinic.reservationRequired |
| google | 集中保存 rating（字串）、reviewCount（數字）、mapsUrl、reviewsUrl、placeId、verifiedAt；不保留空 placeId，不推造識別碼 |

Google Maps URL 的 `@lat,lng` 可能只是視窗中心，不能直接抄成院所座標；CID、`!1s` 片段或 `/g/` 識別不自動等同 Places API 的 `placeId`。

同一官方 LINE 確實提供預約時，可同時放 `socialMedia.line` 與 `appointmentLink`。`clinicNotes` 不重複評分、評論數或整組聯絡資料。Google 只取得部分值時，只修改有證據的值，回報其餘未確認；未讀商家頁不能刷新 `google.verifiedAt`。

## 固定時間、急診與夜診

- `hours` 用簡短文字寫固定門診、固定休診與必要預約限制；`business_hours` 只放可對外就診的固定週時段。百貨營業、手術專用、住院照護及醫師個別值班不直接當一般門診。
- 掛號截止與收診時間分開記：例如「20:30 停止掛號、21:00 收診」，週表結束為 `21:00`，掛號限制放 `hours` 或 `clinicNotes`。不能以停止掛號時間提前截斷門診，也不能漏掉必要提醒。
- `business_hours` 一旦存在須有 `mon` 到 `sun` 七個鍵，時段為 `HH:MM-HH:MM`。`[]` 表示已確認休診，不能拿來表示未知。週時段不完整時保留原結構；新條目可不填此選填物件，不用空陣列補齊未知日。
- 修改固定時段須同步核對 `hours`。跨午夜或 24 小時先讀 `src/lib/businessHours.ts`：目前 `20:00-02:00` 放在開始營業的星期，隔日凌晨由解析器承接；全天可用 `00:00-24:00`。不要再複製一段到隔日；同時檢查時間值有效、分段無重疊。
- 月班表、某醫師排班、臨時休診與一次性加診用 `announcements`；逐日排班格不能直接覆蓋永久週時段。若同一圖卡另有明確的固定每週規則，可分開引用該部分；必要時對照前期班表或正式異動公告，不能只由幾週相同排班推定永久規則。
- `hasEmergencyService: true` 需要院方明確受理目標物種急診的證據。犬貓急診、24 小時住院照護、夜間電話諮詢都不能推定為特寵急診。
- `nightClinic` 只表示夜間門診，不等於急診；可依已確認晚診判定，不自行發明全站統一的夜間起算門檻。晚間有診不能直接開啟急診旗標。
- `emergencyHours` 與已確認急診範圍一致；原有 legacy `emergency` 若與新判定衝突，檢查使用端後同步處理，不留互相矛盾的旗標。
- 院方明確停止急診才能因服務取消改成 `false`；沒有找到公告不等於停止服務。

## 分類、物種、服務與專長

- `typeText` 使用 `特寵診療`、`犬貓診療、特寵診療` 或 `犬貓診療`，依實際範圍選擇。
- 調整分類前讀 `src/lib/petIcons.ts` 的標準標籤與別名，以及 `src/lib/hospitalTypeText.ts` 的顯示邏輯；`pet_category_group` 影響篩選與分類顯示，不能只改 `typeText` 卻保留矛盾分類。沒有對應別名時人工核對，不把函式自動 fallback 當作物種證據。
- `pets` 保留來源明列的物種／範圍；`pet_category_group` 僅做有依據的標準化。不把「小型哺乳類」展開為兔、鼠、天竺鼠等未列物種。
- 有鳥類照片、飼主評論提過守宮、Google 分類寫特殊寵物，都不足以新增對應 `pets`、`services` 或 `specialties`。
- 醫師履歷、他分院病例、檢體送驗或病理服務不等於此分院現行門診受理。來源同時列犬貓與特寵時，服務須保留物種限制，不能把犬貓急救／外科套到特寵。
- 本次未找到舊服務不代表取消；移除須有停辦、服務範圍變更或可證明原資料誤植的依據。純去重或標準化不得擴張、縮減原本醫療範圍。

## 特別門診

院方明確說明特寵受固定時段、指定醫師、額外預約或特別安排限制時，使用 `specialClinic`。單純全院預約制不自動等於特寵特別門診。

- `hasExoticSpecialClinic: true`：限制已確認。
- `label`：短名稱，例如「特寵特別門診」。
- `note`：真正影響就診的限制，不複製完整排班。
- `reservationRequired`：只描述此門診，不改寫成全院限制。
- `sourceLabel / sourceUrl / verifiedAt`：新增或實際重查該門診時一起維護；無證據時保留既有物件與日期。
- 院方明示恢復一般門診或取消原限制時，同步修正旗標、限制文字與預約層級；不只刷新查核日而留下過期限制。

## 公告來源連結

- `website`、`socialMedia` 保存院方入口；公告與更新動態的 `sourceUrl` 優先保存直接對應事件、已實際讀取的獨立公告頁、官方貼文或公告文件連結。能取得事件原文時，不用首頁、粉專首頁或每月覆蓋的門診資訊頁取代。
- 若異動最初只在班表或總頁找到，儲存前從同院已確認的官方入口查找該事件原文。原文無法取得時，可保留直接支持事件與日期的官方班表／總頁，`sourceLabel` 如實標示；在工作回報說明未取得獨立連結或存取受阻，不把未找到寫成沒有公告，也不編造貼文網址。沿用主流程的工具重試與停止條件。
- 目前每則公告／更新只有一組 `sourceLabel`、`sourceUrl`，選最能支持該則內容的事件原文；其他佐證及其支持的細節保留於證據表和 Threads 來源備查。來源名稱須對應實際網址，不能把多個平台名稱寫在單一連結上，假裝已保留全部來源。
- 修正同一事件的原文連結時，同步核對醫院公告、更新動態與已產出的 Threads 來源備查。不同內容若另需其他來源，保留其用途與對應 URL，不把一篇只支持部分內容的貼文當成全部內容的證據。

## 公告與 Facebook 摘要

- 新通知用 `announcements`，不再新增 legacy `specialEvents`。
- 公告依事件使用 `closure / hours_change / service_change / notice`，保留來源連結、查核日及可確認的生效期間。
- 查核未來公告時讀 `src/lib/hospitalAnnouncements.ts`：目前 `startDate` 前不顯示、`endDate` 當日仍顯示。仍填真實事件日期；需要提前提醒的重要事件可按日期與更新紀錄新增 HospitalUpdate，摘要寫清未來生效日。不為提前顯示而偽造事件日期，也不在資料更新任務中改 UI。
- `endDate` 是最後受影響日；院方只說某日休診，不自行補「次日恢復門診」。不連續休診日宜分筆，不能用連續區間誤標中間日期。
- 月份班表可記已確認的月份期間；需同時確認年份。年份不明或圖卡日期看不清時，不新增可能被誤認為當期的公告，也不猜 ISO 日期；舊公告保留並列為待確認。未標結束日的限制不虛構截止日。
- 已結束的公告不描述成即將發生；同院同事件更新既有公告，避免每次查核再新增一份。日期到期不等於所有相關服務限制已解除。
- `fb.last_fb_post_date` 使用實際相關貼文日期，`last_fb_post_text` 精簡保留同篇就診資訊，不記無關行銷文或工具操作過程。不把較早貼文覆蓋成「最新」，也不把 IG 的發布日當成 Facebook 發布日；FB 日期不明時不拼接新摘要與舊日期。
