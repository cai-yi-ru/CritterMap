# 多院委派

只在實際查核兩間以上醫院時使用。本節要求使用 sub-agent，預設每批最多同時 2 間，使用者指定本次數量時依其上限；每個 worker 只查一間、不改檔、不再委派。主 agent 是唯一寫入者。

批次限制是並行上限，不是任務總數。依入口確認的完整清單維護總數、已處理與未處理數，完成一批即接續下一批；只有使用者明確限定任務總數、抽樣或既有條目時才縮小範圍；「一次三間」等每批數量不縮小總範圍。

縣市任務先由主 agent 依 [查找清單外院所](discovery.md) 搜尋並去重候選；每個候選的分院身分確認後，以單院完整查核任務包排入後續批次。新增候選要更新待處理數，不能因既有清單已查完而漏掉候選。

## 分批與工具設定

1. 主 agent 先完成定位，列出每院短代碼、`id / name / address / 檔案`、查核範圍與現有官方 URL；新候選另附發現來源、初步去重結果與缺少的必要欄位。
2. 使用當前 delegation 工具的模型覆寫能力，指定 `gpt-6-luna`、`reasoning_effort: max`。以無歷史或最少歷史派送，避免夾帶其他院所資料；使用者指定優先，不改主 agent 的模型或推理設定。
3. 若工具為 `collaboration.spawn_agent`，使用 `model: "gpt-6-luna"`、`reasoning_effort: "max"`、`fork_turns: "none"`，並附下方完整任務包；其他工具依文件使用等效參數。
4. 首選模型因容量不足、不可用或設定被拒絕而無法執行時，改建備用 worker：`model: "gpt-6-sol"`、`reasoning_effort: "medium"`、`fork_turns: "none"`，沿用完整任務包。同輪後續批次沿用備用設定，不逐院重試已不可用的首選；下次任務重新從首選開始。來源讀取失敗不視為模型故障，依來源停止條件處理。
5. 首選 worker 已無法繼續或中斷時，先確認其狀態並取得可用結果；需要換模型時結束該 worker 的任務，沿用任務包及已驗證線索交給備用 worker。只補缺項，不同時讓兩個 worker 重查同一院；正常長時間查核不視為模型故障。
6. 若備用也不可用、工具不支援模型覆寫或無 sub-agent 能力，主 agent 可逐院循序完成並回報限制；不再自動改用未指定的預設子代理模型。記錄實際模型、推理強度及 fallback 原因，不將備用執行聲稱為 Luna max；使用者禁止 fallback 時回報受阻。

## Worker 任務包

填入實際值後派送；檔案路徑用完整路徑，worker 不應依賴主 agent 的對話歷史：

```text
任務：查核以下一間醫院並提出資料異動建議。只讀，不改檔、不提交預約、不再委派。
CHECK_DATE（Asia/Taipei）：[當次日期；跨日查核另回報實際日期]
短代碼／目標檔案：[值]
醫院 id／name／address：[值]
範圍：[指定欄位及相依欄位，或全院；清單外候選須查新院完整條目]
候選身分（如適用）：[未收錄／疑似同院／新分院；已比對的全站條目 id 及待解缺項]
目前完整物件：[貼入目標物件，或精確位置供讀取；新候選無既有物件時明寫並附已取得證據]
來源入口：[現有官方網站、社群、預約與 Google URL]
必讀：[本 skill 的絕對路徑]、[references/field-rules.md 的絕對路徑]、[src/types/hospital.ts 的絕對路徑]
文字步驟必讀：[references/writing.md 的絕對路徑]、[主 agent 已解析的 humanizer-zh-tw/SKILL.md 絕對路徑]
必要時讀：[references/update-records.md、hospitalTypeText.ts、petIcons.ts、businessHours.ts 的絕對路徑]
使用者約束：[指定瀏覽器、來源限制、是否允許 fallback；無則明寫無]

先核對同院與分院，再查當期來源；官網／正式公告優先，社群次之。
只有院方明示才能改服務、物種、專長、特寵急診或門診限制。
未找到不代表取消；未知不寫 false 或 []。衝突未解保留原值。
未來生效先建議公告，不提前替換現行資料。
搜尋摘要不是已讀原文；同一路徑失敗最多再做一次有目的重試。
文字用客觀台灣繁中，不含宣傳、維護過程或無來源推論。
先完成證據表，再依 writing.md 用 humanizer-zh-tw 潤飾建議文字及回報。
保留日期、數字、名稱、物種、來源與診療限制；來源原文摘錄不潤飾。
不可因文字潤飾刷新查核日期或新增 HospitalUpdate；不附自評分或浮水印詢問。

依下列回報契約返回：
1. 短代碼、id、name、address；同院辨識是否通過。
2. 查核狀態：指定範圍完成／部分／受阻；逐組列已確認不變、已改建議與未解欄位，僅全院範圍可稱完整查核。
3. 逐欄：目前值 → 建議值；擬修改／已確認不變／證據不足／受阻；理由。
4. 每個異動的來源 URL、原文重點、來源日期、生效期間、查核日。公告依 field-rules.md 的「公告來源連結」回報事件原文；使用班表／總頁替代時說明原因，其他佐證另列其支持的細節。
5. 相依欄位：位置、時間、急診、分類與預約層級是否一致。
6. specialClinic、公告、HospitalUpdates：建議內容或不新增理由；區分院方新事件與舊資料校正，限範圍內判定。
7. 未解衝突、受阻來源及保留欄位；無法查核就明說。新候選另回報是否同院、當期特寵受理證據、必要欄位缺項及是否符合新增條件。
8. 文字步驟：已套用 humanizer 且核對語意／本輪無顯示文字／受阻及原因。
```

若 worker 共用同一瀏覽器 session，各自使用專屬分頁，不接管或關閉另一個 worker／使用者的分頁。無法隔離時，瀏覽器步驟改循序。

## 批次完成與主 agent 覆核

- 同批全部 worker 完成或明確受阻後，再逐院整理與套用；完成該批 diff 檢查才派下一批。等待時可檢查已回報來源、既有格式與更新紀錄，勿同時讓 worker 寫檔。
- worker 的摘要不是證據本身。主 agent 核對每個擬修改欄位的 URL、原文重點、分院與生效日期；身分／搬遷、急診、物種或服務範圍變更、來源衝突須親自開啟關鍵來源覆核。
- 缺少證據時只追問具體缺項。能依分院、時效、適用範圍裁決的來源差異要完成裁決，不全部退回待確認；仍不足就保留受影響欄位。補查後同步更新證據表及完成狀態，避免回報仍沿用已解決的缺項。
- 按短代碼逐院套用，重讀目標物件，確認沒有把 A 院電話、物種、公告或來源寫進 B 院。
- 主 agent 對照證據表覆核潤飾後文字；若重新合併或改寫 worker 的文字，再執行文字步驟。worker 標記已潤飾不能取代這項核對。
- 每批核對 diff；全部批次完成後統一執行型別檢查與最終驗證，有新修改或失敗才重跑。
- worker 受阻不阻擋已確認的其他醫院。最後按指定範圍列出完成、部分、受阻、未處理數量、原因與模型 fallback；指定欄位完成不等於完整查核，不將來源不足標記為完整查核。
